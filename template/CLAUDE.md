# 箱の使い方

HTB・CTF の問題を **1問ぶん** 入れる箱。hackdeck の案件のタブで名前を打つと、この雛形を写して作られる
（hackdeck の設定「新しい案件の雛形」の既定がこのフォルダ。作業フォルダ・データ・ログの場所の既定も、この箱の形）。

**このファイルは Claude Code への指示書。** 自分も、運用を確かめるために前半を読む。

> [!warning] 作者が自分用に作り込んだ箱を、見本として写したもの
> 番号やノートの名前は、自分の流儀に合わせて変えてよい。`02-作業`・`91-ログ` の名前を変えたら、このファイルと hackdeck の設定（作業フォルダ・データの置き場所・ログのファイル）も直す。

---

## 自分がやること

これだけ。

| やること | どこに | いつ |
| --- | --- | --- |
| **メモを書く** | `01-メモ/` | 思いついたとき。見出しも順序も要らない。1ファイルで足りなければ分けてよい |
| **範囲を貼る** | `00-案件情報.md` | 範囲（スコープ）が決まっている問題のときだけ。HTB の1台なら空でよい |
| **手を動かす** | `02-作業/` | hackdeck の案件のセッションは、ここで開く。道具の出力もここに落ちる |
| **画面を貼る** | Ctrl+V（どのノートでも） | GUI でしか見えないものを撮れたとき。任意 |

端末で打ったことは `91-ログ/実行ログ.log` に自動で残る（hackdeck が書く）ので、書かなくていい。

**残りは Claude に頼む。** 頼み方は「整理して」「見落としは？」「ヒント」「学びをまとめて」「〇〇するスクリプトを作って」。

## 箱の中身

番号が **誰が書くか** を示す。判定は頭の番号だけなので、後ろの日本語は変えてよい。番号は固定なので、並びは変わらない。

| `11-経過.md` | やったこと・潰した手（理由つき）・まだ追っていない手がかり。追記式 | 整理・見落としの洗い出しのたび |
| `12-資格情報.md` | 資格情報 × サービスの表。**まだ試していない組み合わせ**が分かる | 資格情報が増えるたび |

| `15-ヒント.md` | 頼まれて出したヒントの履歴。新しいものが上 | ヒントを出すたび |
| `16-学び.md` | 次の箱でも使えそうなもの。自分のノートに入れるかは自分が決める | 「学びをまとめて」のとき |
| `18-道具/` | 頼まれて作った使い捨てのスクリプト | 頼まれたとき |

#### `10`・`11`・`14` は重複ではなく、切り口が違う

同じ1つの出来事が、3枚に別の顔で載る。

| | 何として載るか |
| --- | --- |
| `11-経過` | **自分の行動**（何を打ったか・前は何で失敗したか） |
| `10-現在地` | **相手の性質**（いま何が正しいか。毎回上書き） |
| `14-攻撃経路` | **つながった手順**（通った道だけ） |

- `10` と `11` は、うまくいったかを問わない。失敗した試しからも、`10` に載る事実は出る
- `11` の「未消化の手がかり」に事実を書き写さない。書くのは「まだやっていない行為」だけで、事実は `10` を指す
- `14` に失敗を混ぜない。失敗は `11`
- `16` は別枠。この箱の事実ではなく「箱を超えるかもしれない気づき」

## Claude への指示

ここから下は Claude 向け。

### いちばん大事な決まり（学習のため）

- **解くのは本人。** 頼まれていない答えや次の一手を、先に言わない（例外は `10-現在地.md` の「次の一手」1行だけ）
- **ターゲットにリクエストを送らない。** コマンドを打つ・調べる・つなぐ、のどれも本人がやる。Claude が読むのは、この箱のファイルだけ
- 頼まれる仕事は5つ: 整理・見落としの洗い出し・ヒント・学び・使い捨てのスクリプト

### 何をどこに書くか

- **`0x` に書き込まない。** 本人の面。本人が作ったファイルを動かす・名前を変える・消すこともしない
- frontmatter を書かない・触らない
- 各ファイルの先頭に、持ち主のコールアウトを1つ。`> [!tip]`＝本人の面、`> [!abstract]`＝Claude の面。ほかの種類の意味は `92-見本/見た目の見本.md`
- 1行目は空行にする（コールアウトが先頭の行にあると、Obsidian のライブプレビューで枠が描かれない）
- 見出しは `##` から始める（`#` はファイル名が担う）。段を飛ばさない
- 中身の無い表・チェックボックスを置かない（例外は `12` の列の見出しと空の1行。最初の追記で、その空の行を中身に置き換える）。中身が無いときは「まだ無い」と、いつ現れるかを1行で書く
- 新しいファイル・フォルダを、箱の頭に作らない

### 整理する（「整理して」）

`91-ログ/実行ログ.log` と `01-メモ/`、それに `0x`・`1x` のノートを読み、`1x` を **事実で** 埋める。

> [!danger] 事実だけを書く
> 解釈・推測・ヒント・次にやることの示唆を `12`〜`14` に書かない。整理は事実の整理で、助言ではない（ヒントは頼まれたときだけ）。例外は `10-現在地.md` の「次の一手」1行だけ。

- **出どころを必ず付ける。** 端末の実行は `実行ログ.log:L####`、GUI で見たものは `90-添付/<画像>`、本人の判定は `01-メモ/`。この3つに無いことは書かない
- 埋めるために推測しない。読めない欄は空のままにする
- `12-資格情報.md` は追記だけ。行を消さない・並べ替えない。誤りが分かったら、消さずに `備考` に書く

### 見落としを洗い出す（「見落としは？」）

ログ・メモ・`1x` のノート・`02-作業/` の中身を見て、**出ていたのに追っていないもの** を探す。

- 例: 出力に出ていたのに、そのあと触れていないもの／`12` で、まだ試していない組み合わせ／`02-作業/` にあるのに、まだ見ていない結果／同じことを何度もやり直している所
- 見つけたものは、`11-経過.md` の「未消化の手がかり」に **行為の形で** 足す（出どころつき）
- どれが正解かは言わない。それはヒントの仕事

### ヒントを出す（「ヒント」）

- **この箱のファイルから読み取れることだけで考える。** ネットの writeup は見ない
- 先に現在地を調べる: `10-現在地.md`・`01-メモ/`・`14-攻撃経路.md`・ログを読み、本人がどこで止まっているかを特定する
- 段階は3つ。**方向だけ** → **系統まで**（何の種類の弱さか） → **手順**。いちばん弱い段階から始め、**「もっと」と言われるまで次に進まない**
- 出したヒントは `15-ヒント.md` の **いちばん上** に積む。過去のヒントは消さない

```
## 2026-11-02 04:12 ｜ 方向だけ ｜ 話題

本文。

---
```

### 学びをまとめる（「学びをまとめて」）

- `16-学び.md` は、頼まれたときだけ書く。材料はログ・`11`（潰した手こそ学びの源）・`14`・`15`・`01-メモ/`
- 1つにつき、`16-学び.md` の `> [!example]` の5つを書く
- **自分のノートへ入れるかは本人が決める。** こちらから「清書しましょうか」と持ちかけない

### 使い捨てのスクリプト（「〇〇するスクリプトを作って」）

- 置き場は `18-道具/`。`02-作業/`（本人の面）には書かない
- 資格情報を直に書かない（`12-資格情報.md` を読む形に）
- 作ったら `10-現在地.md` に「何を `18-道具/` に置いたか」を1行
- 走らせるのは本人。範囲（`00-案件情報.md`）の中でだけ動くものにし、壊す・取り返しのつかない動きを含むなら、作る前に聞く

### ログの読み方

**全部を一度に読まない。** 大きくなる（10MB を超えうる）。

- コマンドの区切りは、時刻の行（`──── 2026/11/02 04:12:00 ────`）。終わりの行には、かかった秒数が付く
- 増えた分: `10-現在地.md` の末尾の `<!-- log: 実行ログ.log 最終処理行=N -->` から読む（`sed -n 'N,$p'`）。整理したら N を書き直す
- 当たりをつけてから、その前後だけを読む（`grep -n` で行を探し、`sed -n 'A,Bp'` で読む）
- 最後の区切りより後は、終わりまで読む
- 画面を全部使うプログラム（vim など）の中は残らない。プロンプトに戻らない間は、戻ったときに1つのまとまりで残る

### 図

mermaid で描く。ホストが1台でも描く（`13-ネットワークマップ.md`）。表で足りるものは表にし、届き方だけを図にする。
ノードの ID は ASCII の英数字だけ、ラベルは `["..."]` で囲む、改行は `<br/>`。

### 安全

- 範囲の一次は `00-案件情報.md` だけ（空なら、本人が名前を挙げた1台だけ）。ログから推して広げない
- 確かめた事実（`[事実]`。場所・行番号・出力を添える）と、埋めた隙間（`[推察]`）を書き分ける
- スクリーンショットを催促しない。撮るかどうかは本人が決める
- `git push` しない（`01-メモ/` と `12-資格情報.md` には資格情報が入る）
